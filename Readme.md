# 播客留存预测

## 1. 项目概述
本项目旨在预测播客平台用户的重复收听行为（即忠诚度预测）。通过分析用户画像、播客单集属性及交互上下文，构建了一套完整的从数据探索（EDA）、特征工程到多模型对比验证的工业级机器学习流水线。

## 2. 数据探索与分析 (EDA & Analysis)
项目在特征工程之前，通过专项脚本对数据进行了深度体检，为后续模型设计提供了理论支撑：

### 2.1 综合数据探索 (`comprehensive_eda.py`)
*   **缺失值体检**: 识别出 `sex` (57.8%) 和 `scene_name` (37.5%) 的高缺失现状，支撑了“缺失值信号化”的处理策略。
*   **数值分布分析**: 发现 `duration` 的高偏度（Skewness: 13.48），直接推动了 Log 变换的应用；识别出 `age` 存在 1052 岁等极端异常值，确立了分桶处理方案。
*   **相关性探索**: 挖掘出 `tab_name=collections` (0.62) 与 `scene_name=G` (0.68) 的极高转化相关性，为“高意图特征”构建提供了依据。

### 2.2 冷启动专项分析 (`cold_start_analysis.py`)
*   **用户冷启动**: 统计发现测试集包含 14.5% 的新注册用户（影响 7.2% 的行记录），确立了基于画像属性而非 ID 的泛化需求。
*   **内容冷启动**: 识别出 26.6% 的单集为首次出现（影响 12.5% 的行记录），证明了引入 BGE 语义向量增强内容理解的必要性。
*   **双冷启动**: 识别出 0.8% 的极难预测样本（新用户听新单集），明确了系统预测能力的底线边界。

## 3. 特征分析与处理 (Feature Engineering)

### 2.1 数据分布与异常发现 (基于 EDA)
*   **缺失值分析**: 发现 `sex` (57.8%) 和 `scene_name` (37.5%) 存在显著缺失。项目未采取简单的均值填充，而是引入了缺失标识位特征（如 `sex_is_missing`），将缺失本身作为一种业务信号。
*   **异常值识别**: 
    *   `age`: 存在大量 0 值和极端大值（1052）。处理策略：实施分桶编码（Binning），将异常值归为“未知”桶，增强模型鲁棒性。
    *   `duration`: 偏度高达 13.48。处理策略：实施 **Log 变换** ($log(1+x)$)，使其更接近正态分布，优化模型收敛。
*   **类别不平衡**: `tab_name` 和 `scene_name` 呈现显著的头部效应（Top 1 占比分别达 50% 和 70%）。处理策略：通过频率编码（Frequency Encoding）强化高频类别的信号。

### 2.2 特征工程亮点
*   **多维统计特征**: 构建了 `uid_freq`、`episode_id_freq` 以及 `user_avg_duration`，捕捉用户的活跃度和内容的热度。
*   **冷启动应对**: 针对测试集中 14.5% 的新用户和 26.6% 的新单集，设计了基于类目（`first_category`）和语言（`language`）的降级特征。
*   **深度语义集成**: 引入 BGE 预训练模型对播客标题（`title`）进行向量化，提取 16 维语义特征，使模型具备“读懂”内容的能力。
*   **内存优化**: 采用 `reduce_mem_usage` 机制，在保留精度的前提下，将内存占用降低了约 70%。

## 4. 模型训练与调优 (Modeling Strategy)

### 4.1 Pipeline 架构
项目实现了 **解耦式架构**，确保了实验的严谨性：
1.  `preprocess.py`: 特征工程，产出基础特征矩阵。
2.  `split_data.py`: **核心亮点：基于用户生命周期的代理时间划分 (Proxy-based Temporal Split)**。
    *   **背景**: 原始交互数据缺失时间戳，直接进行随机划分会导致“时空穿越”和严重的 ID 记忆泄露。
    *   **逻辑**: 挖掘用户特征中的 `rg_date`（注册日期），利用 **注册序** 作为时间的代理变量。按 `user_tenure`（在站时长）降序排列，即按“注册时间从远到近”排序。
    *   **切分**: 取前 80% 的“老注册用户”作为训练集，后 20% 的“新注册用户”作为验证集。
    *   **意义**: 这种方式强制模型通过老用户的通用规律去预测新用户的留存行为，彻底杜绝了利用未来信息预测过去的风险，真实模拟了推荐系统上线后面对新流量的泛化场景。
3.  `train_*.py`: 独立模型训练脚本，保证所有模型在同一份划分数据上竞争。

### 4.2 多算法横向对比
我们构建了涵盖 **GBDT 阵营** 和 **深度学习 (DL) 阵营** 的全明星阵容：
*   **GBDT**: LightGBM, XGBoost, CatBoost (擅长处理离散特征和非线性关系)。
*   **DL**: DeepFM (二阶交叉), DCN-V2 (显式高阶交叉), **AutoInt (基于 Transformer 的自注意力交叉)**。

## 5. 结果分析对比 (Results)

| 模型 | Overall AUC | Cold User AUC | Cold Episode AUC | 评价 |
| :--- | :--- | :--- | :--- | :--- |
| **LightGBM** | **0.7219** | 0.7218 | **0.6986** | **综合表现最强**，冷启动适应性极佳。 |
| **CatBoost** | 0.7202 | 0.7201 | 0.6900 | 类别特征挖掘能力稳健。 |
| **XGBoost** | 0.7194 | 0.7192 | 0.6872 | 表现均衡，特征重要性集中在场景名。 |
| **AutoInt** | 0.7193 | 0.7192 | 0.6854 | **深度学习中最优**，自注意力机制有效捕捉了特征交互。 |
| **DeepFM** | 0.7167 | 0.7166 | 0.6870 | 基础深度学习 Baseline，表现稳定。 |
| **DCN-V2** | 0.7087 | 0.7086 | 0.6834 | 在本项目数据下出现轻微过拟合。 |

经过实验对比，最终选择**LightGBM**。

### 5.1 评价指标深度解析

| 指标名称 | 业务含义 | 计算逻辑 | 核心价值 |
| :--- | :--- | :--- | :--- |
| **Overall AUC** | **整体验证集 AUC** | 在全量验证集样本上计算的平均排序能力。 | 衡量推荐系统在全站范围内的平均转化预测水平。 |
| **Cold User AUC** | **新用户冷启动 AUC** | 专门针对训练集中**从未出现过**的用户子集计算的 AUC。 | 衡量系统对**新注册用户**的留存预测能力，体现模型的特征泛化水平。 |
| **Cold Episode AUC** | **新内容冷启动 AUC** | 专门针对训练集中**从未出现过**的播客单集子集计算的 AUC。 | 衡量系统对**新发布内容**的挖掘与分发能力，是打破“信息茧房”的关键。 |

### 5.2 核心发现
*   **特征重要性**: `entrance_type` 和 `episode_id_freq` 在所有模型中均位列 Top 3，说明用户的收听入口上下文和内容的流行度是决定留存的最关键因素。
*   **冷启动表现**: 树模型在处理未见过 ID 时表现出更强的鲁棒性（Cold Episode AUC 领先 DL 模型约 1.3%）。
*   **深度学习潜力**: AutoInt 的表现非常逼近 GBDT 模型，说明 Transformer 架构在表格数据特征交互上具有显著优势。

## 6. 工作亮点 (Highlights)

1.  **严谨的验证策略**: 针对无时间戳的难题，创新性地提出 **“基于用户生命周期的代理时间划分” (Proxy-based Temporal Split)**。通过注册序模拟业务演进，不仅杜绝了数据泄露，更让验证集 AUC 具备了评估新老流量交替的实战意义。
2.  **专项冷启动评估**: 建立了 **Overall / Cold User / Cold Episode** 三位一体的评估体系，量化展示了模型在 ID 缺失场景下的鲁棒性，体现了对推荐系统核心痛点的深刻理解。
3.  **多模态特征融合**: 成功将 **NLP 预训练语义向量 (BGE)** 融入传统 CTR 模型，提升了对内容本身的理解深度。
4.  **架构的前沿性**: 实现了基于 **Transformer (AutoInt)** 的特征自动交互模型，体现了从传统统计学模型到前沿深度学习架构的跨越。

## 8. 运行步骤

请按照以下顺序执行脚本，以确保数据流的完整性：

### 第零阶段：数据探索与分析 (EDA)
在建模前，运行以下脚本以深入理解数据分布与业务痛点：
```bash
python comprehensive_eda.py   # 综合数据探索（缺失值、分布、相关性）
python cold_start_analysis.py # 冷启动现状分析（用户/内容冷启动比例）
```

### 第一阶段：数据准备
1. **生成基础特征**:
   ```bash
   python preprocess.py
   ```
2. **执行统一划分** (固定训练/验证集):
   ```bash
   python split_data.py
   ```

### 第二阶段：模型实验 (GBDT)
运行以下脚本进行树模型训练，结果将保存为 `result_*.csv`:
```bash
python train_lgb.py   # LightGBM 实验
python train_xgb.py   # XGBoost 实验
python train_cat.py   # CatBoost 实验
```

### 第三阶段：深度学习实验 (Deep Learning)
1. **生成语义向量** (可选):
   
   ```bash
   python bge_embedding.py
   ```
2. **深度学习专用预处理**:
   ```bash
   python dl_preprocess.py
   ```
3. **运行 DL 模型**:
   ```bash
   python deepfm.py    # DeepFM
   python dcn_v2.py    # DCN-V2
   python autoint.py   # AutoInt (Transformer-based)
   ```
